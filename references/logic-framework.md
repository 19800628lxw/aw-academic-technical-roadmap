# 技术路线图逻辑校验框架 v2.0

美观是形式，逻辑是生命。本框架定义五道逻辑关卡，生成前自查、生成后复核，任何一道不通过即返工。

## 关卡 1：总-分-总骨架

- 图题（课题名称）必须存在，且位于逻辑起点
- 五段式/闭环式必须以"结论与展望"收口；三栏式必须三栏齐备
- 每个阶段/栏目都有明确标题，标题 = "阶段N：动宾短语"（如"阶段三：现状与问题分析"）

**自查**：遮住所有子框只看标题链，能否读出一个完整研究故事？

## 关卡 2：纵向逻辑链（五段式）

标准链：提出问题 → 概念界定与理论基础 → 现状与问题分析 → 现实审察/困境剖析 → 优化解决路径

- 相邻阶段满足"产出→输入"关系：阶段一的"问题"是阶段二理论选择的依据；阶段二的"分析框架"是阶段三调查设计的工具；阶段三识别的"主要问题"是阶段四剖析的对象；阶段四揭示的"机理"是阶段五路径设计的靶点
- 禁止跳段：任何箭头只连接相邻阶段（方法栏虚线关联除外）

**自查**：在每条阶段间箭头上标注"传递物"（如"研究问题清单"），若标不出则该阶段内容缺位。

## 关卡 3：横向并列逻辑（阶段/栏内子框）

- 同一容器内子框必须**同一抽象层级**：不出现"问卷调查"（方法层）与"农民参与意愿低"（发现层）并列
- 3-4 个子框呈 MECE：互斥（不重叠）且穷尽（该阶段该说的都说了）
- 子框命名 ≤ 6 字，动宾或偏正结构统一（全用"XX分析"或全用"XX设计"）

**自查**：给每个子框标注抽象层级标签（概念/方法/发现/对策），同容器内标签必须一致。

## 关卡 4：图文一致（与申报书正文对应）

- 图中每个子框都能在申报书"研究内容"章节找到对应小节，反之亦然
- 研究方法栏列举的方法必须与正文"研究方法"部分一一对应，虚线指向使用该方法的阶段
- 图中不出现正文没有的新概念，不遗漏正文的核心概念

**自查**：左手指图、右手翻目录，逐框打勾。

## 关卡 5：闭环特有校验（逻辑闭环式）

- 节点数 4-6 个，首尾闭合：最后一节点必须有回到首节点的虚线反馈边（标"反馈/迭代"）
- 每个节点回答"输入什么→加工什么→输出什么"，相邻节点输出=下一节点输入
- 多因素交互研究在环上标注双向箭头，而非单环

**自查**：从任一节点出发沿箭头走一圈，能否回到原点且每一跳都有信息增量？

## 生成器内置的逻辑保障

`scripts/gen_roadmap.py` 从机制上保证（无需人工干预）：

1. 阶段串联箭头仅存在于相邻元素间（链条式生成）
2. 方法栏虚线只指向阶段整体，不指向子框（避免层级混淆）
3. 子框自动等宽居中（杜绝因宽度不一暗示的伪层级）
4. 闭环式自动生成末节点→首节点的虚线反馈边

生成后仍需人工过五道关卡——逻辑正确性无法由排版工具保证。
